# Отчёт о бенчмаркинге архитектуры SO33

**Дата:** 2026-05-26
**Ветка:** `claude/benchmark-so33-datasets-2V3I3`
**Статус:** промежуточный (честный срез текущего состояния; исправления и улучшения — отдельным этапом)

---

## Краткое резюме

Инфраструктура бенчмарков для SO33 полностью реализована и прогнана на
синтетических и реальных данных (HIGGS, Top Tagging, UCI Adult). Главный
вывод честный и неоднозначный:

1. **Архитектура работает и численно устойчива** — за исключением одного
   диагностированного бага расходимости (буст-генераторы в per-particle
   режиме); исправление найдено и проверено, но ещё не применено.
2. **Единственное явное преимущество inductive bias — эквивариантность.**
   На синтетическом тесте `so33` даёт согласованность предсказаний
   (consistency) **0.987** против ~0.95 у базовых моделей — это прямое
   подтверждение, что архитектура уважает симметрию SO(3,3) по построению.
3. **По точности на реальных данных SO33 конкурентоспособна, но не выигрывает.**
   На HIGGS немного уступает поточечным активациям при равном числе
   параметров; на Top Tagging — паритет (агрегированное представление) или
   конкурентоспособность (per-constituent).

Рекомендация по позиционированию: вести статью от свойства эквивариантности /
робастности и паритета при равном числе параметров, **не** от рекордной
точности.

## Что реализовано

**Ядро (`so33/`):**
- `SO33Activation` — активация на основе геодезического потока ОДУ на R^{3,3}
  (метрика signature (+++---)), с обучаемой связностью Γ.
- `SO33Network`, `BottleneckClassifier` — единый каркас
  Linear → активация → Linear, общий для всех вариантов.
- Две абляции: `signature_only` (компактная подалгебра so(3)⊕so(3), без бустов)
  и `freeze_coeffs` (фиксированная случайная Γ — «геометрия без обучения»).
- Опция фиксированного шага `rk4` для устойчивости на реальных данных
  (адаптивный `dopri5` склонен к underflow dt).

**Бенчмарки (`benchmarks/`):**
- Загрузчики: HIGGS (UCI), Top Tagging Reference (arXiv:1902.09914, зеркало
  HuggingFace `dl4phys/top_tagging`), нейтральная таблица (UCI Adult).
- `DeepSetsClassifier` — per-particle активация + masked-pool для headline-
  эксперимента Top Tagging.
- Дизайн «двух режимов справедливости»: *matched-bottleneck* (все модели
  сжимаются до hidden=6 — научный вопрос) и *natural-width* (MLP получают
  широкий слой — инженерный вопрос).
- Единый цикл обучения, агрегатор таблиц.

## Результаты

Пометки достоверности:
**[АКТУАЛЬНО]** — получено на текущей версии кода, можно опираться.
**[УСТАРЕЛО]** — данные до исправления бага, **не является результатом**.
**[БАГ]** — численная ошибка, не результат.
**[НЕИНФОРМАТИВНО]** — около случайного уровня / один seed.

### Синтетика: эквивариантность — [АКТУАЛЬНО], ключевой результат

| model | clean_acc | transformed_acc | consistency |
|---|---:|---:|---:|
| **so33** | 0.533 | 0.536 | **0.987** |
| relu_bottleneck | 0.547 | 0.537 | 0.946 |
| gelu_bottleneck | 0.540 | 0.528 | 0.919 |
| so33_signature_only | 0.580 | 0.558 | 0.872 |
| tanh_bottleneck | 0.533 | 0.503 | 0.862 |
| so33_frozen | 0.447 | 0.498 | 0.851 |

`so33` показывает наивысшую согласованность предсказаний под действием
случайных преобразований SO(3,3). **Честная оговорка:** точность у всех
моделей близка к случайной (~0.53) — синтетическая задача мала и/или
недообучена, поэтому эквивариантность здесь означает «стабильно одинаковые»,
а не «стабильно верные» предсказания. Тем не менее это самая чистая
демонстрация того, что архитектура уважает симметрию по построению.

### Синтетика: data-efficiency и OOD — [НЕИНФОРМАТИВНО]

Все модели около случайного уровня (0.46–0.57), один seed. Эти прогоны
сейчас не различают модели и требуют пересмотра (больше данных, ≥3 seed,
более информативная задача). В выводы статьи не годятся.

### HIGGS — [АКТУАЛЬНО]

#### matched bottleneck (hidden=6)

| model | params | test_acc | test_auc |
|---|---:|---:|---:|
| tanh_bottleneck | 188 | 0.699 | **0.768** |
| relu_bottleneck | 188 | 0.701 | 0.767 |
| gelu_bottleneck | 188 | 0.700 | 0.767 |
| so33 | 203 | 0.687 | 0.752 |
| so33_signature_only | 194 | 0.685 | 0.751 |
| so33_frozen | 188 | 0.655 | 0.704 |

#### natural width MLP

| model | params | test_acc | test_auc |
|---|---:|---:|---:|
| tanh_mlp | 7938 | 0.726 | **0.805** |
| relu_mlp | 7938 | 0.726 | 0.804 |
| gelu_mlp | 7938 | 0.725 | 0.803 |

Три честных наблюдения:
- **Обучение Γ помогает:** `so33_frozen` 0.704 → `so33` 0.752 AUC (+0.048
  при том же числе параметров).
- **Полная (3,3) ≈ компактная (3)⊕(3) на HIGGS:** `signature_only` 0.751 ≈
  `so33` 0.752 — кросс-сигнатурные (буст) генераторы здесь почти не дают
  вклада, что согласуется с тем, что признаки HIGGS хорошо описываются
  евклидовой кинематикой.
- **SO33 уступает поточечным активациям** при равном числе параметров
  (~0.752 против 0.767 AUC). Это честный отрицательный результат для данного
  датасета.

### Нейтральная таблица (UCI Adult) — [УСТАРЕЛО], нужен повторный прогон

| model | params | test_acc |
|---|---:|---:|
| все модели | — | 0.760 |

В агрегаторе все 9 моделей показывают одинаковые 0.760 = доля мажоритарного
класса Adult. **Это артефакт бага декодирования меток** (метки OpenML
приходили как bytes/int, а сравнивались со строкой `">50K"` → все метки
обнулялись). Баг исправлен (коммит `81d9a88`) + добавлена защита от константных
меток. Эти числа получены **до** исправления и подлежат перепрогону; после
исправления MLP должны давать ~0.85.

### Top Tagging, агрегированное представление — [АКТУАЛЬНО]

#### matched bottleneck (hidden=6)

| model | params | test_acc | test_auc |
|---|---:|---:|---:|
| tanh_bottleneck | 56 | 0.890 | 0.938 |
| relu_bottleneck | 56 | 0.889 | 0.938 |
| gelu_bottleneck | 56 | 0.889 | 0.938 |
| so33 | 71 | 0.887 | 0.936 |
| so33_signature_only | 62 | 0.887 | 0.936 |
| so33_frozen | 56 | 0.887 | 0.907 |

Все модели сходятся к ~0.938 AUC. Причина: `aggregate_jet_to_6d` сворачивает
струю в 6 признаков уровня струи, включая **инвариантную массу** — главный
дискриминант top vs QCD. Признак вычислен заранее и выдан всем моделям, поэтому
даже логистическая регрессия достигла бы ~0.938. **Честное прочтение:** при
готовых лоренц-инвариантных признаках уровня струи архитектура не важна. Этот
результат сохранён как вторичный baseline. (Слабый сигнал всё же есть:
`so33_frozen` 0.907 < остальных.)

### Top Tagging, per-constituent (Deep Sets) — headline, [ЧАСТИЧНО / БАГ]

#### matched bottleneck (hidden=6)

| model | params | test_acc | test_auc |
|---|---:|---:|---:|
| gelu_bottleneck | 44 | 0.700 | 0.751 |
| tanh_bottleneck | 44 | 0.691 | 0.750 |
| relu_bottleneck | 44 | 0.699 | 0.749 |
| so33_signature_only | 50 | 0.692 | 0.738 |
| so33_frozen | 44 | 0.669 | 0.720 |
| **so33** | 59 | 0.497 | **nan [БАГ]** |

#### natural width MLP

| model | params | test_acc | test_auc |
|---|---:|---:|---:|
| relu_mlp | 1794 | 0.710 | 0.762 |
| tanh_mlp | 1794 | 0.705 | 0.757 |
| gelu_mlp | 1794 | 0.703 | 0.757 |

`so33` (полная обучаемая связность) **разошёлся в NaN** — отсутствует AUC, acc
на уровне случайного (0.497). Это единственный вариант с обучаемыми
**буст-генераторами**; `signature_only` (без бустов) и `frozen` (малая
фиксированная Γ) устойчивы. Подробности и исправление — в разделе «Известные
проблемы».

Даже устойчивые варианты SO33 (`signature_only` 0.738, `frozen` 0.720) **не
обгоняют** поточечные базовые модели (0.749–0.762). Абсолютные числа здесь
низкие у всех (~0.74–0.76), так как leading-32 + masked-mean + hidden=6 —
слабая архитектура (для сравнения, ParticleNet даёт ~0.98). Значим именно
относительный итог: SO33 конкурентоспособна, но не выигрывает.

## Интерпретация

- **Положительное и доказуемое:** SO33 эквивариантна по построению, что
  подтверждено эмпирически (consistency 0.987). Это самое сильное и честное
  утверждение для статьи.
- **Информативные абляции:** обучение Γ улучшает результат (frozen < learned
  на HIGGS); на HIGGS полная (3,3) не превосходит компактную (3)⊕(3) —
  буст-структура там не нужна.
- **Честный отрицательный итог:** выигрыша по точности на HIGGS и Top Tagging
  нет. На HIGGS — небольшое отставание; на Top Tagging — паритет/конкуренция.
- **Вывод для позиционирования:** заявлять не «обгоняем всех по точности», а
  «эквивариантная архитектура с доказуемым свойством инвариантности,
  конкурентоспособная при равном числе параметров». Это корректная и
  защищаемая постановка.

## Известные проблемы

1. **Расходимость `so33` в per-constituent режиме (NaN).**
   *Причина:* буст-генераторы so(3,3) некомпактны; при обучении больших
   коэффициентов Γ геодезический поток под индефинитной метрикой растёт
   экспоненциально, фиксированный rk4 выдаёт inf → NaN, и одна расходящаяся
   итерация отравляет все веса.
   *Подтверждение:* воспроизведено на синтетике — текущая конфигурация даёт
   NaN на шаге 81 (норма коэффициентов → nan).
   *Исправление (проверено, ещё не применено):* `bound_input=True` для Deep
   Sets SO33 — нормировка входа каждой частицы ‖x‖<1. Результат: устойчиво,
   норма коэффициентов 0.30. Применяется только к per-particle пути (в плоском
   HIGGS-пути bound_input ухудшал сигнал, поэтому там он выключен).

2. **Нейтральная таблица устарела.** Метки Adult исправлены (коммит `81d9a88`),
   нужен повторный прогон `run_neutral`.

3. **Везде один seed** — нет доверительных интервалов; для статьи нужно ≥3 seed.

4. **Синтетический battery (dataeff/OOD) около случайного уровня** — задача
   слишком мала/сложна, требует пересмотра.

---

## Дальнейшие шаги (отложено)

1. Применить `bound_input=True` к Deep Sets SO33, перепрогнать
   `top_tagging --representation constituents` — получить валидное число вместо
   NaN.
2. Перепрогнать `run_neutral` с исправленными метками.
3. Многосидовые прогоны (≥3) для доверительных интервалов.
4. Опционально — дать inductive bias более честный шанс на точность:
   физически мотивированное вложение 4-импульса в R^6 вместо обучаемого Linear,
   sum-pool вместо mean-pool, больше per-particle ёмкости.

## Воспроизведение

```bash
# Данные
pip install huggingface_hub pandas pyarrow tables
python -m benchmarks.download_top_tagging --cache-dir data   # Top Tagging
# HIGGS.csv(.gz) и Adult загружаются загрузчиками автоматически

# Реальные данные
python -m benchmarks.run_higgs       --cache-dir data --max-samples 200000 --epochs 30
python -m benchmarks.run_neutral     --epochs 30
python -m benchmarks.run_top_tagging --cache-dir data --representation aggregated   --max-samples 100000 --epochs 30
python -m benchmarks.run_top_tagging --cache-dir data --representation constituents --n-constituents 32 --max-samples 100000 --epochs 30

# Синтетика
python -m benchmarks.run_synthetic_equivariance
python -m benchmarks.run_synthetic_dataeff
python -m benchmarks.run_synthetic_ood

# Сводные таблицы
python -m benchmarks.aggregate
```

Все прогоны пишут `results/<experiment>__<model>__seed<N>.json`; `aggregate.py`
собирает из них таблицы. **Важно:** агрегатор читает все JSON в `results/`,
включая устаревшие — перед финальным отчётом папку `results/` стоит очистить и
перепрогнать целиком на одной версии кода.
